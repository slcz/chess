# chess — a self-play chess AI

A chess engine that improves itself by playing. The play path is
hand-written C — bitboard rules, strictly-legal move generation, PUCT-MCTS
search, and the NN input encoder (64 square tokens, 8-ply history). The
learner is a hand-written PyTorch transformer (axial 2D-RoPE, policy +
WDL + opponent-reply heads) trained on its own search-improved games.
PyTorch is used only as a tensor/autodiff backend.

The pipeline was **bootstrapped once from supervised pretraining** on
human games: human knowledge entered exactly once, as the initial weights
(**gen1**, the 42k-step supervised net). Everything after that is pure self-play —
playout-cap-randomized (KataGo PCR) games generated by disposable cloud
containers, trained via a memory-frugal streaming ingest, and gated by
head-to-head matches.

**Current state (Oct 2026):** gen2 = one self-play round from gen1
(280k games, 300/50-sim PCR, lr 2e-5) — gate **0.639** vs gen1 over 400
games, Stockfish-ladder crossover ≈ **1835** vs ≈ **1730** (≈ +100 Elo).
The full ops loop (container images, HF dataset/ckpts, scripts) is
documented in [SKILL.md](SKILL.md).

## Roadmap

1. **Hyperparameter tuning** — sweep lr / batch / PCR budgets / epochs
   around the gen2 recipe; every candidate must pass the gate (≥ 0.500
   vs its base), tracked by the Stockfish-ladder crossover.
2. **Bootstrap from zero knowledge** — rerun the loop from a randomly
   initialized network (no supervised seed) and measure what the
   human-data bootstrap actually bought.
3. **Serverless web GUI** (`wasm-serverless` branch, Oct 2026) — DONE
   for the core: one static page ([web/](web/), no server) replaces the
   Python play/replay servers (both retired with `chess_ai/uci.py`).
   Engine compiled to WASM — single-threaded with a **stepped eval**:
   `puct_think_start` returns to JS whenever a bank awaits evaluation,
   the page runs the net (onnxruntime-web, WebGPU EP) between steps, and
   `puct_zone_publish` resumes the search. No SharedArrayBuffer, no
   cross-origin isolation, no io thread in the wasm build — plain
   WASM 1.0 on any static host. Native builds keep the threaded io path;
   a Node gate proves the wasm search transcript bit-identical to native
   (`web/test/`). Walkthrough input is SPSHARD1 v3 only (shards opened
   client-side; π + eval come free from the bytes; legacy v1/v2 shards
   convert with `scripts/spbin_to_v3.py`) — PGN playback is
   left to external viewers; the external-UCI opponent mode is dropped
   (`uci_mux`/`sf_gauntlet` stay — pipeline/calibration, not GUI).

## Development setup

```sh
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
make -C engine check                              # C build + unit tests + perft suite
.venv/bin/python -m pytest tests/ -q              # FFI gates + oracle fuzz + data-path parity
```

Training/generation run on salad.com cloud GPUs (RTX 3090/4090/5090),
treated as preemptible cattle: every long-running job is checkpointed,
pushes artifacts off-instance, and keeps no durable state on a box.
